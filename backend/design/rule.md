# 后端编码约定

已确认：Node.js + TypeScript + NestJS 12（Fastify 适配器）+ `@nestjs/swagger`；Better Auth 管会话；CASL 做权限判定；PostgreSQL + Prisma 7 为存储。

## 分层与边界

- 接口层负责协议适配和输入输出，不承载复杂业务流程。
- 业务规则与基础设施细节分离；存储、消息和外部服务通过明确边界接入。大模型调用放在 `src/llm/`，业务层只传入已脱敏的上下文并校验输出。
- 跨层数据契约保持稳定、简单、可验证，避免把内部实现直接暴露给调用方。
- 输入在系统边界校验；权限校验默认在可信服务端执行。
- 登录与会话由 Better Auth 处理，不要把前端持有的令牌当作权限真相。
- CASL 只负责判定；Nest Guard 负责拒绝未登录和无权限请求。未登录返回 401，已登录但角色不够返回 403。列表查询必须带角色或归属条件，禁止只在内存里丢弃结果。
- 数据访问通过明确边界接入 PostgreSQL，不把存储细节泄漏到接口层。课时、冲突等不变量还要落在数据库约束和事务里。

## HTTP 路径与鉴权

Nest 控制器挂在全局前缀 `/api` 下。`SessionGuard` 对 Nest 业务路由默认生效。

| 前缀 | 鉴权 | 说明 |
|---|---|---|
| `/api/auth` | 否（Better Auth） | 登录、退出、读当前会话。不是业务资源。 |
| `/api/common` | 否 | 公开接口。也可用 `@Public()` 标记例外。 |
| `/api/{resource}` | 是 | 先校验会话，再按角色做 CASL 判定。 |

业务资源用 REST 路径，例如 `GET /api/students/:studentId`：本期仅老师/管理员可访问，其他角色 403。学生只能看自己时用 `GET /api/me` 这类别名——这是举例，本期不做。

不要用员工 `/api/me` 承担「当前登录者是谁」。前端读 `GET /api/auth/get-session`。

## 抽象与错误处理

- 保持高内聚、低耦合，不创建只改名并透传参数的包装层。
- 仅在承载规则、隔离变化、统一副作用或明显减少重复时新增抽象。
- 错误应保留可诊断上下文，对外信息不得泄露密钥、内部路径或敏感数据。
- 超时、重试、幂等性和事务边界按实际风险设计，不默认无限重试或静默吞错。

## 实现与验证

- 命名表达领域含义；避免魔法值、隐式全局状态和职责混杂的超长函数。
- 文件名和目录名使用 kebab-case，不含大写字母。细则见 `docs/code-conventions.md`。
- 配置与代码分离，敏感配置只从受控环境读取。
- 测试覆盖核心规则、失败路径和边界条件；外部系统使用可控替身或独立集成测试。
- 格式化、静态检查和测试以仓库已有配置为准；尚未配置时不擅自引入工具。
